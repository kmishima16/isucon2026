ISUReal 画面と API の対応（検証役、2026-10-31 手元の docker で確認）

確かめた環境

  • 手元の compose：postgres:16（操作役の部分ダンプ。users 5043・posts 625200）＋ アプリ（webapp/go、ISUREAL_REGION=asia の 1 台）＋ nginx（server/all/.../isureal.conf）。
  • 初期ユーザー yuma_kobayashi_186（asia）でログインした。新規登録した asia の利用者でも確かめた。
  • 画像はほぼすべて 403。ダンプで image_objects のデータを抜いたため（image_api.go:45-52 は行が無いと 403）。本番では 200 のはず。
  • 画面ごとに 30 秒待って通信を記録した。生の記録は raw/log-*.json（巡回）と raw/ops-*.json（操作）。
  • 管理者の API（/api/admin/*）を呼ぶ画面はフロントエンドに無い。投稿期間の開始（POST /api/admin/posting-window）と認定はベンチマーカーだけが呼ぶと見ている（推測）。そのため、通知が届く流れは手元で確かめていない（未確認）。

どの画面でも呼ぶもの（ログイン後）

  • GET /api/me：画面を開くたびに 1〜3 回。設定の画面では 2 回呼ぶ。
  • GET /api/notifications：画面を開くたびに 1 本。SSE の形のロングポーリング（Accept: text/event-stream を fetch で読む。EventSource ではない）。通知が無ければ 30 秒のあいだ応答が返らなかった。1 件返すと接続を閉じ、クライアントはすぐ（受信が無いときは 1 秒後）に呼び直す。
    • サーバーは接続ごとに 500ms おきに getUser と notifications の SELECT を回す（notification_api.go:37-60）。つないでいる利用者の数 × 毎秒 2 回 × 2 クエリが DB に乗る。
  • GET /api/images/:id?exp&sig：画像を出す画面で、画像ごとに 1 回。署名つき URL で、ログインは要らない。応答は no-store。

画面ごと

ログインが要るかと書き込みの有無は、表示時の呼び出しについて書く。

  • ログイン /login：ログイン不要。表示時は API を呼ばない。操作時 POST /api/auth/login（JSON：username・secretKey）。成功後にホームへ移る。
  • 新規登録 /register：ログイン不要。操作時 POST /api/auth/register（JSON：username・displayName・region）→ 201 で SecretKey を画面に出す。ログインはされない（続けて /login で入る）。書き込みあり。
  • ホーム（フィード）/ ・/feeds/friends・/feeds/friends-of-friends・/feeds/public・/feeds/following：表示時 GET /api/posting-window/current と GET /api/feeds/:feed。タブを替えるたびに両方を呼び直す。スクロールで続きを取る（beforeXxx と beforeId の形のページング、JS の Sr）。
    • 今日まだ投稿していない利用者では、My friends に「投稿すると、友達の写真が見られます。」と出て、GET /api/feeds/friends を呼ばなかった（新規登録の利用者で確認）。
    • 公開フィードは、今の投稿期間（10:23 開始）の投稿 3 件だけが出た。
  • 撮影・投稿 /posts/new：表示時は共通の 2 つだけ。カメラ（getUserMedia）か画像ファイル（JPEG）を選ぶと、?step=settings でキャプション・公開範囲（友達・友達の友達・公開）・位置情報を設定する。操作時 POST /api/posts（multipart：image・caption・visibility・locationKind・latitude/longitude・locality）→ 201 で /posts/complete へ。書き込みあり。
    • 同じ投稿期間に 2 回目は 409 post_slot_unavailable（画面は「今日はすでに投稿済みです」）。初期ユーザーは投稿済みだった。
    • 409 のあとに GET /api/posting-window/current を呼び直す。
  • 投稿完了 /posts/complete：API は共通のものだけ。
  • 自分の現在の投稿 /posts/me/current：表示時 GET /api/posts/me/current。操作時 PATCH /api/posts/:id（キャプション・公開範囲の「変更を保存」）、DELETE /api/posts/:id（削除）。PATCH と DELETE は JS からの読み取りで、実行はしていない。
  • 投稿詳細 /posts/:id：表示時 GET /api/posts/:id。
  • コメント /posts/:id/comments：表示時 GET /api/posts/:id と GET /api/posts/:id/comments（afterCreatedAt・afterId で続き）。操作時 POST /api/posts/:id/comments（JSON：body）→ 201、続けて GET /api/posts/:id/comments を呼び直す。削除は DELETE /api/comments/:id（未実行）。書き込みあり。
  • RealMoji /posts/:id/realmoji：表示時 GET /api/posts/:id と GET /api/posts/:id/realmojis。操作時 POST /api/posts/:id/realmojis（multipart：reactionType・image。JPEG で 512px 以下。超えると 400 invalid_realmoji）→ 201、続けて GET /api/posts/:id/realmojis。同じ投稿へは置き換え（replaceRealMojiHandler）。削除は DELETE /api/realmojis/:id（未実行）。書き込みあり。
  • Memories /memories：表示時 GET /api/memories?month=YYYY-MM（beforePostedAt・beforeId で続き）と、各投稿の画像。月を替えると呼び直す。
  • Memories の投稿 /memories/posts/:id?month=：GET /api/memories?month= を呼び直して、その中から出す（専用の API は呼ばない）。
    • サーバーの GET /api/memories/:date を呼ぶ画面は無かった。ベンチマーカーだけが呼ぶと見ている（推測）。
  • 通知 /notifications：共通の 2 つだけ。受けた通知は画面の中で持つ（地域を替えると消す）。
  • つながり /relationships/:kind（friends・following・followers・incoming-requests・outgoing-requests）：表示時 GET /api/relationships/:kind（beforeUpdatedAt・beforeId で続き）と、相手のプロフィール画像。操作時：友達解除 DELETE /api/friendships/:userId、申請の承認・拒否・取消 POST /api/friend-requests/:id/:action（未実行）。
  • ユーザー検索 /users：表示時は共通のものだけ。操作時 GET /api/users?q=（検索ボタン）。
  • ユーザー /users/:id：表示時 GET /api/users/:id。操作時：フォロー PUT /api/follows/:userId → 204、友達申請 POST /api/friend-requests（JSON：recipientId）→ 201。どちらも続けて GET /api/users/:id を呼び直す。フォロー解除 DELETE /api/follows/:userId、ブロック PUT・DELETE /api/blocks/:userId、友達解除 DELETE /api/friendships/:userId（未実行）。書き込みあり。
  • プロフィールメニュー /settings：表示時は共通のものだけ。操作時 POST /api/auth/logout → 204 で /login へ。
  • プロフィール設定 /settings/profile：操作時 PATCH /api/me（JSON：displayName・bio）→ 200。プロフィール画像は PUT /api/me/profile-image（image/jpeg の生のバイト列）・DELETE /api/me/profile-image（未実行）。
  • 地域設定 /settings/region：操作時 PATCH /api/me（region）と見ている（JS の pi。未実行）。地域が替わると、セッションの地域とアプリの地域が合わず、以後 403 region_mismatch になる。フロントは isureal:region-changed を出して通知をつなぎ直す。手元はアプリが asia の 1 台なので確かめていない（未確認）。
  • SecretKey の確認 /settings/secret：API は共通のものだけ（端末に保存した値を出す）。
  • エクスポート /settings/export：操作時 GET /api/me/export（Accept: application/zip）→ 200。全投稿の画像と JSON の ZIP。
  • アカウント・データ /settings/account、退会 /settings/delete：退会は POST /api/me/account-deletion（未実行）。

調査役へのメモ

  • 1 画面を開くと、少なくとも GET /api/me と GET /api/notifications が呼ばれる。notifications は接続のあいだ、500ms おきに DB を叩き続ける。
  • フィード・Memories・つながりは、画像の数だけ GET /api/images を呼び、その 1 回ごとに 2 回 SELECT する（image_api.go:43-91）。
