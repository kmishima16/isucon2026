# reboot-test

全台を再起動し、何もせずに動くかを見る再起動試験です（本番の追試と同じ観点）。

## 役割

- 再起動の前後で、DB の全テーブルの行数が変わらないこと（書き込んだデータが残ること）を確かめる。
- 再起動後に `HEALTH_URL` が中身のある 200 を返すことを確かめる。DB に届かないと空の 200 を返すアプリがあるため。
- DB を止めたままアプリを起こし、15 秒後に DB を起こしても、アプリが自力で戻ることを確かめる。再起動では、アプリが DB より先に起きることがあるため。`DB_LATE=0` で省く。
- MySQL / MariaDB を前提にする。

## いつ使うか

- 依頼された作業を終えて報告する前で、最後の reboot-test より後に deploy しているとき（CLAUDE.md の出来事ごとの手順 7）。続けて `make bench`。
- 本番の最終盤（docs/flow/contest.md）。

## 動かし方

- scripts/reboot-test.sh の冒頭のコメント、`make help`。

## 確かめ方

- 「全テーブルの行数が再起動の前後で同じです」「DB があとから起きても戻りました」「全台復帰」が出る。
- 行数の記録は logs/<時刻>-rows-before.tsv と rows-after.tsv に残る（手順 7 の判断にも使う）。
- ssh が戻らないときは `make doctor`。

## 更新のしかた

- 確かめるページ：isu.env の `HEALTH_URL`。DB を読むページにする（空の応答や 204 を返すページだと失敗扱いになる）。
- 直したら `make lint`。練習環境で、ベンチの後に通す（書き込みがある状態で行数を比べるため）。
